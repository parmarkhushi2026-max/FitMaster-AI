2. Computer Vision & Repetition Counting Algorithm

Mathematical angle computation and Finite State Machine (FSM) hysteresis

A. Biomechanical Vector Angle Formulation

For any tracked anatomical joint \( B \) (e.g. Knee or Elbow) connected to adjacent skeletal points \( A \) (e.g. Hip) and \( C \) (e.g. Ankle), the angle \( \theta \) is computed using the 2D planar vector dot-product:

Vector u = (Ax - Bx, Ay - By)
Vector v = (Cx - Bx, Cy - By)

θ = | arccos( (u · v) / ( ||u|| * ||v|| ) ) | * (180 / π)

// Equivalent trigonometric implementation in Javascript:
const radians = Math.atan2(c.y - b.y, c.x - b.x) - Math.atan2(a.y - b.y, a.x - b.x);
let angle = Math.abs((radians * 180.0) / Math.PI);
if (angle > 180.0) angle = 360.0 - angle;
return Math.round(angle);

B. Finite State Machine (Hysteresis Rep Counter)

5. Specialized System Algorithms

DOM internationalization, nutrition mathematics, and multi-currency engine

A. Safe Non-Destructive DOM Tree-Walker Algorithm

Traditional i18n scripts overwrite element.innerHTML or element.textContent, which permanently destroys nested icons (<i class="fa">) and event listeners. FitMaster solves this using a Recursive DOM Text-Node Walker:

function walkTextNodes(element, callback) {
  const walker = document.createTreeWalker(element, NodeFilter.SHOW_TEXT, null, false);
  let node;
  while ((node = walker.nextNode())) {
    const trimmed = node.nodeValue.trim();
    if (!trimmed) continue;
    if (!node._origVal) node._origVal = node.nodeValue; // Cache immutable original
    callback(node, trimmed);
  }
}

B. Mifflin-St Jeor Daily Macro & Calorie Algorithm

Implemented on the homepage for clinical-grade metabolic estimations:

// Basal Metabolic Rate (BMR)
For Males: BMR = (10 × weight_kg) + (6.25 × height_cm) - (5 × age) + 5
For Females: BMR = (10 × weight_kg) + (6.25 × height_cm) - (5 × age) - 161

// Total Daily Energy Expenditure (TDEE)
TDEE = BMR × ActivityFactor (Sedentary: 1.2, Light: 1.375, Moderate: 1.55, Heavy: 1.725)

// Target Protein Prescription

6. Viva / Interview Questions & Master Explanations

Frequently asked questions by academic examiners & technical recruiters

Q1: Why did you use MediaPipe in the browser instead of running OpenCV on the Django server?
Answer: Latency and server cost. Sending 30 to 60 FPS video frames over HTTP/WebSocket to a backend server creates immense network congestion and requires heavy GPU servers. By executing Google MediaPipe Pose via WebGL/WebAssembly directly on the user's client browser, we achieve zero network latency, maintain 100% user camera privacy (video never leaves the device), and our server costs remain near zero.
Q2: How does the system prevent false repetition counts when someone wobbles or moves slightly?
Answer: We implemented a Finite State Machine with Hysteresis. Instead of incrementing reps at a single point, the algorithm requires the athlete to cross two distinct angular thresholds: the "contraction threshold" (e.g. ≤ 95° for squats) followed by an "extension lockout threshold" (e.g. ≥ 155°). Small tremors inside the intermediate zone are ignored.
Q3: How is Role-Based Access Control (RBAC) enforced in Django?
Answer: We created a Profile model with a OneToOne relationship with Django's built-in User. Each profile stores a role ("admin", "trainer", "customer"). Custom view decorators check role permissions before execution and redirect unauthorized requests to safe dashboard routes.
Q4: What happens if the Google Gemini API quota expires or goes offline?
Answer: FitMaster includes a resilient multi-tier fallback engine. When Gemini API is unavailable or unconfigured, the view routes the query through our built-in regex-based kinetic fitness knowledge engine, answering inquiries regarding workouts, nutrition, supplements, and splits instantly.
Q5: How does the multi-currency system ensure pricing integrity?
Answer: All database prices are securely normalized in base INR (₹). When a user selects a region (US, UK, UAE, EU, etc.), client-side currency multipliers recalculate the display prices with currency symbols, while the transaction records store both the base amount and transaction currency.
