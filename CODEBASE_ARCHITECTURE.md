## 📂 1. Directory Structure & Folder Purpose Guide

| Folder Path | Category | Detailed Purpose & Responsibility |
| :--- | :--- | :--- |
| **`FitMaster/`** | Project Root Config | Core Django project module containing global settings, WSGI/ASGI configurations, and master URL routing. |
| **`users/`** | Primary Django App | Main application handling user authentication, role management (Customer, Trainer, Admin), views, database models, signals, and unit tests. |
| **`users/management/`** | Management Commands | Custom Django CLI commands, including data seeders (`seed_data.py`) to populate default packages, products, and admin users. |
| **`users/migrations/`** | Database Migrations | Database schema migration files tracking changes to models over time. |
| **`accounts/`** | Auxiliary Module | User account package modularized for legacy or isolated user operations. |
| **`templates/`** | HTML Templates | Contains 38+ HTML template files rendered by Django views, structured into base layouts, customer, trainer, admin, and error views. |
| **`templates/includes/`** | Partial Templates | Reusable partial HTML components such as `admin_sidebar.html` and `trainer_sidebar.html`. |
| **`static/`** | Development Static Assets | Raw static files including custom CSS stylesheets (`theme.css`, `navbar.css`, etc.) and original images/icons. |
| **`staticfiles/`** | Compiled Production Assets | Compiled and optimized static directory automatically generated by WhiteNoise via `collectstatic` for production delivery. |
| **`logs/`** | Application Logs | Stores application logs (`fitmaster.log`) and error logs (`errors.log`) generated by Django's rotating file handlers. |
| **`venv/`** | Virtual Environment | Isolated Python virtual environment containing project dependencies (`Django`, `WhiteNoise`, `ReportLab`, `Waitress`, `Gunicorn`, etc.). |

## ⚙️ 3. Core Django Package (`FitMaster/`)

- **`FitMaster/settings.py`**: Master configuration file containing `load_dotenv()`, security flags (XSS, No-Sniff, Frame Options), `WhiteNoise` static engine, `dj-database-url` database abstraction, email backend, and rotating file logger system.
- **`FitMaster/urls.py`**: Root URL dispatcher routing `users.urls`, Django admin (`/django-admin/`), media static files, and custom error handlers (`handler404`, `handler500`, `handler403`).
- **`FitMaster/wsgi.py`**: WSGI interface for production servers (`Waitress`, `Gunicorn`).
- **`FitMaster/asgi.py`**: ASGI interface for asynchronous execution.

## 🗄️ 4. Database Models Index (`users/models.py`)

- **`Profile`**: Extends Django `User` model via OneToOneField to enforce Role-Based Access Control (`customer`, `trainer`, `admin`).
- **`TrainerDetail`**: Stores specialized trainer categories (`gym`, `yoga`, `pilates`, `cardio`).
- **`Package`**: Gym membership subscription packages (3 Month, 6 Month, 1 Year).
- **`Membership`**: Active customer subscription records with start and expiry dates.
- **`Payment`**: Financial transactions log for memberships and store purchases.
- **`Client`**: Maps trainer-to-customer assignments and goals.
- **`WorkoutPlan`**: Custom exercise routines assigned by trainers.
- **`DietPlan`**: Custom daily meal plans assigned to clients.
- **`Schedule`**: Training appointment calendar.
- **`Progress`**: Trainer-logged fitness evaluation metrics and notes.
- **`Measurement`**: Customer self-logged height/weight logs with automatic BMI.
- **`Feedback`**: Customer ratings and reviews.
- **`Notice`**: Broadcast announcement notifications.
- **`Product`**: Supplement store inventory items.
